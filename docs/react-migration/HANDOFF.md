## 3. Architecture decisions that matter

1. **No FastAPI / no backend.** Per `WNBA_CLOUDFLARE_REACT_CONVERSION.md` §41
   the React frontend reads only precomputed JSON served as static assets.
   `frontend/src/api/dataClient.ts` is the only fetch path; its base URL
   defaults to `/data/` (Vite serves `public/` from the site root) and is
   overridable via `VITE_DATA_BASE_URL` for production R2 hosting.

2. **Existence-and-shape contract.** `scripts/export_web_data.py` reads the
   existing canonical pipeline outputs (parquet under
   `data_files/wnba/normalized/`, evaluation JSON, source health, paper
   ledger) and emits a stable set of JSON envelopes with explicit
   `schema_version: 1`, ISO-8601 `generated_at`, `league_key: "wnba"`.
   `scripts/validate_web_data.py` rejects NaN/Infinity, missing required
   fields, unknown secrets, and size-budget overruns (>50% over target =
   fail; 1–50% over = warning).

3. **Streamlit remains untouched.** The Streamlit app, `pages/`,
   `utils/`, `scripts/`, `.github/workflows/`, and the existing pytest
   tests are all preserved. The exporter is additive.

4. **Scenario Lab parity.** `tests/build_scenario_fixtures.py` uses an
   in-script Mulberry32 PRNG (a clean re-implementation of the same
   algorithm as the TS port) so the two implementations are bit-comparable
   within IEEE-754. The production `utils/market_simulation.simulate_player_prop`
   continues to use `numpy.random.default_rng(seed)` (PCG64); the parity
   fixture generator is **not** a substitute for the production code.

5. **No chart library.** A small inline-SVG `LineChart` keeps the bundle
   at ~222 KB minified (~70 KB gzip). Same colour and dimensions as
   Streamlit's `st.line_chart` for the two charts that ship today (team
   rolling points, player points).

6. **Visual parity, not visual redesign.** The React UI follows
   `00A_VISUAL_REFERENCE.md` faithfully — sidebar layout, page headings,
   metric card arrangement, probability-bar colours, confidence badges,
   "NO BET · PAPER ONLY" pill, etc.

## 5. Known gotchas (read before continuing)

1. **Streamlit server can be hijacked.** During this session a stale
   Streamlit process from a *different* project was already bound to
   `:8501`. The parity harness would silently drive the wrong app and
   report "expected text not present" on every page. **Before running
   `scripts/test_react_parity.py` verify with `Test-NetConnection
   127.0.0.1 -Port 8501`** and `curl http://127.0.0.1:8501/` — the
   response body should contain "WNBA" or "Betting Oracle", not
   "Predictions / Players / Matches / Tournaments / Odds / Tools".

2. **vite preview must use strictPort.** The harness expects both
   servers on fixed ports. `vite.config.ts` already has `strictPort:
   true`. If 4173 is occupied, kill the holder first.

3. **Mulberry32 vs numpy default_rng.** The TS port and the Python
   parity fixture generator both use Mulberry32 with seed=42 for
   bit-identical Monte Carlo. The production Python simulator continues
   to use `np.random.default_rng(42)` (PCG64) and was NOT modified. The
   parity fixture tolerance for player-prop is 1e-6 (bit-comparable);
   for the parlay it is 0.01 because the parlay fixture uses
   `np.random.default_rng` inside `_simulate_correlated_parlay` to
   match the production path.

4. **TypeScript `noEmit: true`.** `npm run build` runs `tsc --noEmit &&
   vite build`. This avoids the `tsc -b` project-references gotcha
   (the tsconfig.node.json file was removed; see git history if you
   revert it).

5. **The parity harness's Streamlit path uses polling**, not
   `wait_for_selector("#root")` (the Streamlit "Loading…" placeholder is
   hidden and breaks the wait). It waits on `stHeader` then polls
   `body.innerText` for expected substrings for up to 30s, then sleeps
   2s more before screenshotting.

6. **Per-season data files.** `export_web_data.py` writes
   `standings_<season>.json`, `team_stats_<season>.json`, and
   `player_stats_<season>.json` for every season found under
   `data_files/wnba/normalized/{standings,team_game_stats,player_game_stats}/season=*/`.
   The un-suffixed files (`standings.json`, etc.) carry the **current**
   season (per `config/league.toml`). This matches the Streamlit
   behaviour where season selection re-runs the loader for a different
   year.

7. **Visual parity report baseline.** The current
   `docs/react-migration/parity/` screenshots are dated from the most
   recent successful React run. They need to be paired against a clean
   Streamlit run before the parity report can be written; the current
   `perf/streamlit.json` and `perf/console-errors.json` were produced
   before the wrong-app Streamlit was killed. Re-run the harness after
   fixing §6 below.

8. **The performance harness's "tti_estimate_ms" field is `DCL +
   load + startTime`**, which is not a true Lighthouse TTI (no 5s-quiet
   window). It is sufficient as a parity-comparable analogue and is
   called out as such in the perf report.
